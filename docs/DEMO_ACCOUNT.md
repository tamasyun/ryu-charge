# デモアカウント

通常のログイン画面で `demo@example.com` を入力し「ログイン」を押すと入れる。メール送信・認証コード・Supabase上のユーザー作成は行わない。アドレスの定義は `src/demo/account.js` の `DEMO_EMAIL`。

地図・教室一覧・投稿フォーム・アカウント設定は通常アカウントと共通。入ったときだけポップアップで保存範囲を案内する。

- 公開情報はセッションを保存しない匿名クライアントで取得する。60秒ごととウィンドウに戻ったときに再取得し、ブラウザ内の追加分を重ねる。
- 教室・コンセント・レビュー・写真・ユーザー名・パスキーの公開鍵情報は、このオリジンの `localStorage`（`ryu-charge:demo:v1`）に保存する。公開情報のスナップショットは保存しない。
- デモのログイン状態は `sessionStorage` に置く。ログアウト後も追加分は残り、同じブラウザ・オリジンで再ログインすれば続けられる。通常アカウントにはデモの追加分を表示しない。
- 写真も画像処理後にブラウザ内へ保存する。容量不足時はエラーを表示し、サーバー保存に切り替えない。
- 本番クライアントはデモ利用中の書き込みを通信直前で拒否し、匿名クライアントは常にGET・HEAD以外を拒否する。

「アカウント設定 → パスキー管理」では、端末のWebAuthn登録画面を使う。登録後はログイン画面にデモ用アドレスを入力し「パスキーでログイン」できる。ログイン時はチャレンジ・オリジン・RP ID・本人確認フラグ・署名をブラウザ内で検証する。これはデモ用のローカル認証であり、Supabaseの認証には使わない。

パスキーの秘密鍵は端末またはパスキープロバイダーが管理する。ブラウザデータやデモアカウントを削除しても、端末側のパスキーは自動削除されない。ブラウザ側の登録情報を消した場合や別オリジンでは使えないため、不要なパスキーは端末の設定から削除する。

デモのアカウント削除は、このブラウザのデモデータだけを消す。本番DB・Storage・Authに変更は加えない。

検証は `npm run lint`、`npm test`、`npm run build`。`demoBrowser.test.mjs` は公開データの応答を差し替え、通常画面での投稿、最新公開データとの合成、再読込、ログアウト後の分離、Chromium仮想認証器でのパスキー登録と再ログイン、モバイルWebKitの操作を確認する。OSの実パスキー画面・実機Safariの確認は別途必要。
